# Ошибки которые нужно избежать — FreelancePaymentAgent

> Это не лог прошлых ошибок — это список ТИПИЧНЫХ ошибок на каждом этапе.
> Читай перед каждым этапом чтобы не наступать на грабли.

---

## На этапе Валидации

### ❌ Ошибка: Начать строить до валидации
**Почему опасно:** Потратишь 2 недели на код → выяснишь что никому не нужно
**Правило:** 30 signups на waitlist = минимум для начала build. Ни одной строчки кода раньше.

### ❌ Ошибка: Рекламный пост на Reddit вместо истории
**Почему опасно:** Reddit банит рекламу. Посты удаляются, аккаунт банится.
**Правило:** Пост = личная история о боли. Упомяни продукт в конце или в комментарии. Не в заголовке.

### ❌ Ошибка: Считать "лайки" вместо emails
**Почему опасно:** 500 лайков ≠ 500 клиентов. Email в waitlist = реальный интерес.
**Правило:** Метрика валидации = количество email адресов, не просмотры.

### ❌ Ошибка: Не разговаривать с людьми
**Почему опасно:** Landing page говорит что хочешь ты, не то что нужно им.
**Правило:** Поговори с 5 фрилансерами лично/в DM. Задай 3 вопроса: как сейчас решают, сколько теряют, заплатят ли $39.

## На этапе Build

### ❌ Ошибка: Добавлять фичи сверх MVP
**Почему опасно:** Каждая лишняя фича = +1 неделя → задержка запуска → конкурент запускается раньше
**Правило:** Всё что не в CHECKLIST.md для MVP — записать в backlog, не строить сейчас.

### ❌ Ошибка: Не настроить RLS в Supabase
**Почему опасно:** Без Row Level Security один пользователь может увидеть данные другого.
**Правило:** RLS включается ДО первого деплоя. Шаблон SQL в roadmap.

### ❌ Ошибка: Хранить API ключи в коде
**Почему опасно:** Если код попадёт на GitHub — ключи скомпрометированы.
**Правило:** Все ключи только в `.env.local` (локально) и Vercel Environment Variables (продакшн). `.env.local` в `.gitignore`.

### ❌ Ошибка: Деплоить без теста Stripe webhook
**Почему опасно:** Пользователь оплатил → webhook не сработал → подписка не активирована → злой пользователь
**Правило:** Тестировать webhook локально через `stripe listen --forward-to localhost:3000/api/stripe/webhook` перед деплоем.

### ❌ Ошибка: Пропустить бесплатный тариф
**Почему опасно:** Пользователь не может попробовать без карты → высокий barьер → мало signups
**Правило:** MVP = 2 инвойса бесплатно. Stripe только для 3-го и далее.

### ❌ Ошибка: Игнорировать мобильную версию
**Почему опасно:** 40%+ фрилансеров откроют с телефона
**Правило:** Проверить на iPhone/Android перед запуском. Tailwind responsive классы решают 80% проблем.

## На этапе Запуска

### ❌ Ошибка: Product Hunt в неправильное время
**Почему опасно:** PH сбрасывает рейтинг в 00:01 PST. Если запустить в 15:00 PST — у тебя только 9 часов вместо 24.
**Правило:** Запускать строго в 00:01-01:00 PST (это 8:01-9:00 утра по Москве).

### ❌ Ошибка: Просить накрутить upvotes на PH
**Почему опасно:** PH банит аккаунты за координированное голосование с одного IP/устройства.
**Правило:** Можно просить друзей поддержать — но органически, не массово в одно время.

### ❌ Ошибка: Не отвечать на комментарии в день запуска
**Почему опасно:** PH алгоритм учитывает engagement. Комментарии без ответов = меньше visibility.
**Правило:** В день запуска быть онлайн 8 часов, отвечать на каждый комментарий.

### ❌ Ошибка: Отправить waitlist один email и забыть
**Почему опасно:** Из 30 signups 20 забудут о тебе если не напомнить.
**Правило:** 3 email: (1) "Скоро запуск", (2) "Запускаемся сегодня!", (3) через неделю "Вот что говорят первые пользователи".

## После Запуска

### ❌ Ошибка: Игнорировать churn
**Почему опасно:** Если 3 человека отменили подписку в первый месяц — это сигнал. Игнорируешь → теряешь всех.
**Правило:** При каждой отмене: отправить email "Почему уходите?" и прочитать ответ.

### ❌ Ошибка: Добавлять функции вместо разговора с клиентами
**Почему опасно:** Строишь то что думаешь нужно, а не то что реально нужно.
**Правило:** Первые 10 клиентов = созвониться с каждым хотя бы раз.

### ❌ Ошибка: Масштабировать рекламу до Product-Market Fit
**Почему опасно:** Льёшь деньги в рекламу → люди приходят → уходят через неделю → деньги потрачены зря.
**Правило:** PMF = удержание > 80% через месяц. Только после этого увеличивай рекламный бюджет.

## Технические ошибки (специфично для Next.js + Supabase)

### ❌ Использовать `supabase.auth.user()` на сервере
Это устаревший метод. Использовать `supabase.auth.getUser()` в Server Components.

### ❌ Забыть `await` перед Supabase запросами
Приводит к тому что данные не загружаются, а ошибок нет — просто пустой экран.

### ❌ Не обрабатывать ошибки Claude API
Claude может вернуть невалидный JSON. Всегда оборачивать в try/catch + fallback.

### ❌ Деплоить без `NEXTAUTH_SECRET` или `NEXTAUTH_URL`
Если используешь NextAuth — без этих переменных аутентификация ломается в production.
